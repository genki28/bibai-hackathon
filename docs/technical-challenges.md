# 技術的な課題

[何を作るか](product.md) を実現するうえで、技術的に気をつけることのまとめです。
**重要度が高いもの(デモに直接影響するもの)から順に** 並べています。
LINE の料金や API の条件は変わることがあるので、使う前に公式の説明で確かめてください。

## 早めに決めないと進まないこと

### 1. データの保存先 → Supabase に決定

依頼・参加者・ポイント・「誰と一緒に雪かきしたか」を Supabase(= ネット上の無料で使えるデータベース)に保存します。

- 役割・依頼・本人確認の結果を保存する部分はつないだ(表は `supabase/migrations/0001_init.sql`、手順は [05-deploy.md](05-deploy.md))
- 秘密の値(接続用のキー)は `.env` に入れ、コードやドキュメントに書かない
- 個人情報(住所など)を誰が読めるか、の設定(行レベルセキュリティ)に注意する

### 2. 公開 URL(公開方法)が決まっていない

LINE とつなぐには `https://` の固定 URL が必要です。今の一時的な URL(トンネル)は、PC を閉じると使えなくなり、起動のたびに URL が変わります。

- 変わるたびに LINE 側の Webhook URL と LIFF のエンドポイント URL を登録し直す必要がある
- 決まった時間に通知を送る機能(05)は、サーバーがずっと動いている必要がある
- 候補: **Cloudflare Workers**(無料。決まった時間に処理を動かす Cron Triggers も使える)。今のサーバー(Express)を少し書き換えれば載せられる見込み

### 3. LINE で送れるメッセージの数(ハッカソン中は気にしなくてよい)

LINE 公式アカウントの無料プランには、こちらから送るメッセージ(プッシュメッセージ)の月ごとの上限があります。
デモの規模なら足りる見込みなので、ハッカソン中は気にしないことにしました。本番で人数が増えたら見直します。

## 機能を作るときに気をつけること

### 4. お年寄り用と若者用の出し分け

同じ公式アカウントに、使う人が 2 種類います。

- LINE には **ユーザーごとに別のリッチメニューを出す仕組み** があるので、最初に役割を選んでもらい、メニューを切り替える
- 役割の選び間違い・変更の方法も用意しておく

### 5. 場所の扱い(地図と個人情報)

- 住所を地図のピンにするには、住所 → 緯度経度の変換(ジオコーディング)が必要
- 地図は Leaflet + OpenStreetMap(無料)が候補
- **お年寄りの正確な住所を誰にでも見せるのは危険**。「ここに行く」を押すまでは町名レベルのおおよその位置だけ見せる、などの工夫が必要
- デモでは架空の住所を使う(実在の人の住所を使わない)

### 6. 同じ依頼を取り合う・誰も来ない

- 複数人参加を前提にするが、「何人まで」「誰かが向かったら他の人に知らせるか」を決める必要がある
- 誰も行かない依頼が放置されないよう、時間がたったら再通知する、などの仕組みもいずれ必要

### 7. 雪かきの量をどう測るか

- 雪の量は **「面積 × 積雪の深さ」で計算する**。面積は地図で囲むか選択肢から選び、深さは Open-Meteo から取る(詳しくは [03 助けに行く](features/03-go-help.md))
- **3D スキャン(複数の角度の写真から立体を作る)は使わない**。真っ白な雪は写真同士の同じ点を見つけにくく立体になりにくい、大きさの基準が写真だけでは分からない、処理が重く無料のサーバーでは動かない、LIFF からは距離センサー(LiDAR)を使えない、のため
- 写真は量の計測ではなく、AI による 3 段階判定・不正対策・お年寄りへの報告に使う。AI は有料、写真には個人情報が写る点に注意
- 消費カロリーは「METs × 体重 × 時間」の目安。体重は個人情報なので、任意入力にする

### 8. ランキングの不正対策

ポイントが絡むと、ずるをする人が出る可能性があります。

- 「開始」を押して放置するだけで時間を稼ぐ → 作業時間に上限を設ける、お年寄りの「いいね」がない場合はポイントを減らす
- 招待リンクで自分の別アカウントを誘う → 「誘われた人が実際に雪かきを完了したら」だけポイントを入れる
- 本格的な対策はデモの後でよい

### 9. 天気予報 API

- Open-Meteo は登録不要・無料で降雪量が取れる。ただし商用利用は有料プランが必要
- 予報は外れることがある。「積もりそう」はあくまで目安と書く

## 安心・安全に関わること

### 10. 知らない人が家に来る不安

お年寄りにとって、知らない若者が家に来るのは不安です。

- 本人確認(マイナンバーカード連携)は今回は見た目だけの仮実装(モック)。画面は `/liff/identity.html`、仕組みは `src/identity/`。確認結果は Supabase の `identity_verifications` 表に保存する(未設定ならメモリ)
- 本番では、デジタル庁の「デジタル認証アプリ」などの本人確認サービスとつなぐ想定(利用には申請・審査が必要)
- **マイナンバー(12 桁の番号)そのものは扱わない**(法律で使い道が厳しく制限されている)
- 発表では「本人確認済みの人だけが行ける」「家族にも通知が届く」などの安心の仕組みを説明できるとよい

### 11. LINE を使えないお年寄り

- スマホや LINE を使えないお年寄りもいる
- 家族が代わりに依頼する、電話で受け付ける、などは将来の課題として発表で触れられるとよい
