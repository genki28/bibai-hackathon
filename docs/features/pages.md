# 画面(ページ)の一覧

LIFF(= LINE の中で開く Web 画面)のページと、その URL の一覧です。
画面の流れは Miro の遷移図(チームのボード「20261122ハッカソン」)をもとにしています。

## URL の書き方

| どこで開く | URL |
| --- | --- |
| LINE の中(リッチメニューやトークのリンク) | `https://liff.line.me/{LIFF ID}/{ページ}` |
| 自分の PC(`npm run dev` で起動中) | `http://localhost:3000/liff/{ページ}` |
| デザインのおためし(Python の簡易サーバー) | `http://localhost:8000/{ページ}?preview` |

`{ページ}` には下の表のファイル名が入ります(例: `help-waiting.html`)。
`?id=依頼ID` が付くページは、どの依頼の画面かを URL で受け取ります(画面どうしが自動で付けます)。

## 画面のつながり

```text
お年寄り:  [たすけて] → 1 フォーム → 2 待機画面 ─(取り消し)→ 取り消しました。
                                         └(雪かきが終わる)→ [いいねを送る] → 3 いいね

若者:      [ランキング] → 4 ランキング
           [助けに行く] → 5 助けに行く(一覧 → 場所 → 確認の小窓 → 確定 = 参加)
             → 本人確認 →(自動)→ 6 場所・詳細 →[到着しました!]→ 7 待機中
             →(到着した人のだれかが開始 = リーダーがランダムに決まる)→ 8 雪かき中
             →[雪かきを終える]→ リーダー: 9 範囲 →[雪かき終了!]→ 10 お疲れ様
                                 リーダー以外: 「リーダーを待つ」表示 →(終わったら自動)→ 10 お疲れ様
             10 お疲れ様 →[メイン画面に戻る]→ 4 ランキング
```

## 途中から戻る(スリープ・LINE を閉じたあと)

雪かきの途中でスマホをスリープにしたり、LINE や LIFF の画面を閉じたりしても、続きに戻れます。

### リッチメニューから開き直したとき

`go-help.html`(リッチメニューの「助けに行く」)と `ranking.html`(「ランキング」)は、開いた瞬間(覆いを出したまま、一覧を見せる前)に `GET /api/help-requests/active/:userId` で参加中の雪かきを調べ、あればその段階の画面へ移ります(`navigateTo(..., { replace: true })`)。

| いまの段階 | 移る先 |
| --- | --- |
| 参加したが未到着(本人確認の途中で閉じた場合も) | `helper-place.html?id=` |
| 到着済み・開始前 | `helper-gather.html?id=` |
| 雪かき中(リーダーが範囲の画面に進んでいた場合も) | `helper-working.html?id=`(リーダーは [雪かきを終える] で範囲の画面へ) |
| 終わって 1 時間以内 | `finish.html?id=`(この端末でお疲れ様の画面をもう見ていれば移らない) |
| どれでもない | 移らない(いつもの画面) |

- 行き先の決め方は `public/liff/resume-route.js`(テストは `tests/resume-route.test.ts`)、呼び出しは `public/liff/resume.js`
- URL に `?list=1` が付いているときは移らない。下のタブ・「メイン画面に戻る」・「ほかの依頼をさがす」・参加の取り消し後のリンクには `?list=1` を付けている(付けないと、一覧へ戻ろうとしてもまた自動で移ってしまう)
- お疲れ様の画面を見た依頼の ID は、この端末(localStorage の `bibai-seen-finish-ids`)に覚えておく
- 調べるのに失敗したときは移らずに、いつもの画面を出す
- 本人確認(デモ)の途中で閉じた人は `helper-place.html` に戻る。いまの流れでは、本人確認を終えていなくても到着・開始はできる(サーバーは確かめていない)

### 画面が隠れて、また見えたとき

`visibilitychange`(画面が見える状態に戻った)と `pageshow`(保存されていた画面がそのまま戻ってきた)で、すぐ依頼を読み直して表示を合わせます(`public/liff/request-page.js` の `onPageVisible`)。

- 数秒ごとの読み直し(`startPolling`)は、画面が隠れている間は止め(電池の節約)、見えた瞬間に 1 回読み直してから再開する。対象: `helper-gather.html`・`helper-working.html`(リーダーを待つ表示も)・`help-waiting.html`(お年寄り)
- 状態が進んでいれば次の画面へ(例: 待機中に開始されていたら雪かき中へ、雪かき中にリーダーが終えていたらお疲れ様へ)
- `helper-working.html` は経過時間とレベルもすぐ合わせ直す(開始時刻はサーバーにある)
- `helper-working.html` のスコップ計は、オンにしていれば揺れを読み直す(値が 2.5 秒届かなければ、iPhone で許可が切れたとみなしてボタンを出し直す)。スリープ中は数えない
- `helper-place.html` も、見えたときに読み直して、雪かきが始まっていれば雪かき中へ移る
- `snow-area.html`(リーダーが範囲を描く画面)は読み直さない(終えられるのはリーダーだけなので、ほかの人の操作で状態が変わらない)

## 依頼の状態

```text
waiting(募集中)→ accepted(だれか参加)→ working(雪かき中)→ done(終了)
どこからでも(終了前なら)→ cancelled(お年寄りが取り消し)
```

- 1 つの依頼に参加できるのは 5 人まで(仮)
- 開始(accepted → working)は、到着した参加者ならだれでもできる。開始した瞬間に、その時点の参加者からランダムで 1 人をリーダーに決めて `leaderUserId` に残す(到着済みの人を優先。途中参加の人はリーダーにならない)。決め方は `src/help-requests/leader.ts`
- リーダーの役割は「雪かきを行った範囲に丸を付ける」ことだけ。終了(working → done)できるのはリーダーだけ
- 参加者全員がやめると waiting に戻る(開始前なのでリーダーはまだいない)

## API の一覧

すべて `{ success: true, data }` か `{ success: false, error: "日本語のメッセージ" }` で返します。
入力がおかしいと 400、権限がないと 403、依頼がないと 404、いまの状態ではできないと 409。

| API | 入力 | 中身 |
| --- | --- | --- |
| `POST /api/help-requests` | `{ userId, amount?, name?, address?, lat?, lng?, depth?, tools? }` | 依頼を登録(同じ人の終わっていない依頼があればそれを返す) |
| `GET /api/help-requests` | なし | 参加できる依頼の一覧(大まかな情報だけ。名前・住所・正確な位置は出さない) |
| `GET /api/help-requests/mine/:userId` | なし | お年寄りの進行中の依頼(取り消し・いいね済みは除く)。なければ null |
| `GET /api/help-requests/active/:userId` | なし | 若者がいま参加している雪かき(参加中 accepted・雪かき中 working・終わって 1 時間以内の done)を、その人から見た形で。なければ null。続いているものを優先。判定は `src/help-requests/active.ts` |
| `GET /api/help-requests/:id?userId=` | なし | 依頼の詳細。本人と参加者にはすべて、ほかの人には大まかな情報だけ |
| `POST /api/help-requests/:id/join` | `{ userId, displayName }` | 参加する |
| `POST /api/help-requests/:id/leave` | `{ userId }` | 参加をやめる(雪かき開始前だけ) |
| `POST /api/help-requests/:id/arrive` | `{ userId }` | 到着した |
| `POST /api/help-requests/:id/start` | `{ userId }` | 雪かき開始(到着した参加者ならだれでも。到着前は 403)。このときリーダーがランダムに決まり、`leaderUserId` に入る |
| `POST /api/help-requests/:id/finish` | `{ userId, areaM2 }` | 雪かき終了(リーダーだけ。ほかの人は 403「リーダー(〇〇さん)だけです」。面積は 0〜5,000㎡)。スコアを計算して保存 |
| `POST /api/help-requests/:id/scoops` | `{ userId, count, calories? }` | スコップ計のすくった回数を残す(参加者の `helpers[].scoops`)。雪かき中(working)だけ(ほかは 409)・参加者だけ(403)・回数は 0〜3,000 の整数(ほかは 400)。前より増えたときだけ書き換える。ポイントには入れない |
| `GET /api/help-requests/:id/points?userId=` | なし | お疲れ様の画面用。その依頼で自分がもらったポイント `{ workPoints, stars, ratingPoints, reunion: { points, partners: [名前] }, firstFinishBonus, total, scoops: { mine, total } }`(参加者だけ・終わった依頼だけ)。`scoops` はスコップ計の自分の回数とみんなの合計で、`total`(ポイント)には入れない |
| `POST /api/help-requests/:id/cancel` | `{ userId }` | 依頼の取り消し(依頼した本人だけ) |
| `POST /api/help-requests/:id/location` | `{ userId, lat, lng, accuracy? }` | 向かっている若者の現在地を残す(参加者の `helpers[].location = { lat, lng, accuracy, at }`)。参加者だけ(403)・状態が accepted / working で本人が未到着のときだけ(ほかは 409)・緯度 20〜46 / 経度 122〜154(日本のまわり)・誤差 0〜10,000m(ほかは 400)。返事は送った人から見た形(位置は入らない) |
| `POST /api/help-requests/:id/thanks` | `{ userId, ratings: { 若者のユーザーID: 1〜5 } }` | いいね(依頼した本人だけ・1 回だけ) |
| `GET /api/ranking?period=daily\|total&userId=` | なし | ポイントの多い順 `[{ rank, displayName, points, breakdown: { work, rating, recruit, reunion }, isMe }]`。`userId` を付けると自分に `isMe: true` が付く |
| `GET /api/invites/mine?userId=` | なし | 自分の招待コード `{ code }`(なければ作る)。招待リンクは `https://liff.line.me/{LIFF ID}/index.html?invite=コード` |
| `POST /api/invites/accept` | `{ userId, code }` | 招待リンクで開いた人を「誘われた人」として 1 回だけ記録 `{ accepted, reason? }`。自分自身(`self`)・記録済み(`already-recorded`)・持ち主のいないコード(`unknown-code`)は記録しない。誘った人の ID は返さない |
| `GET /api/snow-map` | なし | 美唄の雪山マップ用 `{ piles: [{ id, lat, lng, area, finishedAt, members: [{ displayName, calories }], totalCalories }], totals: { piles, people, calories } }`。終わった雪かき 1 件 = 雪山 1 つ。位置は約 100m に丸め、住所・お年寄りの名前・ユーザー ID は出さない。カロリーはアプリで測った値(なければ時間から出した値) |
| `GET /api/teams/mine/:userId` | なし | 自分が入ったチームと消費カロリーの合計 `{ totalCalories, teamCount, partners, teams: [{ id, finishedAt, area, members: [名前], teamCalories, myCalories }] }`(新しい順)。ランキングの代わり |
| `GET /api/community` | なし | 仲間ゲージ `{ members, goal, baseline }`。members = 終わった依頼に関わった人の重複なしの人数、goal = baseline(10)× 2 |
| `GET /api/config` | なし | 画面用の設定 `{ liffId, testMode, testUsers }`。testUsers はテストモードのときだけ中身がある |
| `POST /api/test/reset` | なし | テスト用の利用者が関わったデータを消す `{ deletedRequests, deletedInvites, userIds }`(招待コードと招待の記録も消す)。テストモードのときだけ(オフなら 404) |

## スコップ計(雪かき中の画面)

スマホの加速度センサー(`devicemotion`)で、雪をすくった回数を数えます。提案は [../proposals/01-measure-snow.md](../proposals/01-measure-snow.md) の「A. スコップ計」。

- 数え方は `public/liff/scoop-counter.js`(ブラウザに依存しない純粋関数。テストは `tests/scoop-counter.test.ts`): 重力を除いた加速度(`acceleration`。なければ `accelerationIncludingGravity` から、約 1 秒でゆっくり追いかける平均 = 重力を引く)の大きさを、直近 5 サンプルの平均でなめらかにし、6 m/s² を超えて 3 m/s² より下がったら 1 回。1 回のあと 0.7 秒は数えない。しきい値は仮で、実機で調整する
- 画面の部分は `public/liff/scoop-meter.js`: iPhone は [📱 スコップ計をオンにする] を押した処理の中で `DeviceMotionEvent.requestPermission()` を呼ぶ。拒否・使えない端末は「この端末ではスコップ計が使えません(画面の経過時間で記録します)」
- 回数は端末(localStorage の `scoop-meter:依頼ID` に `{ count, isOn }`)に覚え、開き直しても続きから。サーバーには 10 秒ごと・[雪かきを終える] を押したとき・画面が隠れたときに送る(送れなくても端末の回数は残る)
- 1 杯の重さは 3.5kg(仮。`KG_PER_SCOOP`)。**ポイントには入れない**(手で振るだけで増えるので、実機で正確さを確かめてから決める)
- テストモードのときだけ [🧪 揺れをまねる] が出て、押すと 1 回すくったことになる(PC で試す用)
- 回数は Supabase の表の `help_requests.helpers`(jsonb)の各参加者に `scoops` として入るので、表の変更はいらない

## みんなで動かした雪と音の実況(雪かき中の画面)

雪かき中はスマホを見られないので、**音と声** で盛り上げる。サーバーや表の変更はない(スコップ計の回数をそのまま使う)。

- **みんなで動かした雪**(`snow-moved.js` が決まり、`moved-meter.js` が表示): みんなのすくった回数 × 1 杯 3.5kg(ほかの人はサーバーから 3 秒ごと、自分は端末の回数)。重さのたとえ(お米 10 袋 100kg / グランドピアノ 300kg / 軽自動車 700kg / ふつうの車 1500kg)を超えるとファンファーレ。**雪の総量は目安しかないので、「あと少し」のような残りやゴールは出さない**
- **音の実況**(`sound-coach.js`): すくうたびに「ザクッ」(Web Audio で作る音。音のファイルはない)。節目はブラウザの読み上げ(speechSynthesis)で 1 つだけ言う。優先順は たとえの重さを超えた > みんなで 50 杯ごと(「みんなで50杯、約175キロ動かしました!」)> 自分の 10 杯ごと。[🔊 音の実況] のボタンでオン / オフ(端末に覚える)
- **画面を消さない**(`wake-lock.js`): スコップ計をオンにすると、画面が消えないようにする(Screen Wake Lock API)。使えない端末では何もしない
- スマホは、ボタンを押した処理の中でしか音を出し始められない。スコップ計・音のボタンを押したときに準備する
- LINE の中のブラウザで、読み上げと画面を消さない設定が使えるかは実機で確かめる(未確認)

## 音の合言葉(スマホを近づけて到着)

若者のスマホが、自分の合言葉(4 桁)を **人には聞こえにくい高い音** で鳴らし、お年寄りのスマホがマイクで聞き取ると、その若者が「到着」になる。GPS と違って、音は玄関先くらいの近さでしか届かないので「本当に来た」証拠になる。[到着しました] のボタンは予備として残している。

- **若者**(目的地の画面 `helper-place.html`、`helper-sound-code.js`): [📡 合言葉を鳴らす] で鳴らし続ける(3 分まで)。3 秒ごとに読み直し、着いたら待機中の画面へ
- **お年寄り**(待機画面 `help-waiting.html`、`elder-sound-arrive.js`): 向かっている人がいる間だけ [📡 来た人のスマホを聞く]。聞き取れたら「〇〇さんが着きました!」(3 分まで)
- **音の作り方**(`sound-code.js`): 「はじめの合図 → 数字 4 つ」を 1 つ 140 ミリ秒ずつ、数字ごとに違う高さの音で鳴らす(FSK)。高い音は 17.5〜18.8kHz。高い音が出ない・拾えない端末のために [聞こえる音にする](1.0〜2.9kHz)もあり、聞く側は両方を同時に聞く
- **聞き取り方**: マイクの音を 20 ミリ秒ごとに周波数に分け(FFT)、候補の中でいちばん大きく、雑音より 15dB 以上大きい音を記号とする。2 回つづいたら「聞こえた」とする(一瞬の雑音は捨てる)
- **合言葉**(`src/help-requests/arrival-code.ts`): 依頼 ID + 若者の ID と、サーバーだけが知っている秘密(LINE のチャネルシークレット)から作る(HMAC)。表には保存しないので、Supabase の表の変更はいらない。となり合う数字は同じにしない
- **API**: `GET /api/help-requests/:id/arrival-code?userId=` — 参加した若者本人に、自分の合言葉を返す(ほかの人は 403)。`POST /api/help-requests/:id/arrive-by-sound` `{ userId, code }` — 依頼したお年寄りだけが送れる。合った若者(まだ着いていない人)を到着にする(違えば 400「合言葉が違います。」)
- 音はどこにも送らない(スマホの中で周波数を調べるだけ)。送るのは聞き取った 4 桁だけ
- テストモードでは、お年寄りの画面に [🧪 合言葉をまねる](マイクを使わず、画面の中で鳴らして聞く)
- 何人も同時に鳴らすと音が混ざって聞き取れないことがある(1 人ずつ近づける)。LINE の中のブラウザでマイクが使えるか、機種ごとに高い音が出る・拾えるかは実機で確かめる(未確認)

## 美唄の雪山マップ(`/snow-map.html`。LIFF ではない普通の Web ページ)

- だれでも見られるページ。終わった雪かき 1 件が、地図の上の **3D の雪山** 1 つになる。一緒にやった全員の消費カロリーの合計が多いほど、大きく高い雪山になる
- 3D の地図は MapLibre GL(登録不要)+ OpenFreeMap の地図。Google マップのような白い浮いた部品・丸いボタン(3D / 2D・ぐるっと回す・美唄全体)・下のシート
- 開くと雪山が下から育つ。**縮尺に合わせて、近くの雪山は 1 つの大きな雪山にまとまる**(引くほど広く。同じ人のカロリーは足す)。引いても見えるように、雪山の見た目は大きくする
- 雪山を押すと、一緒にやった人の消費カロリーの棒グラフ。画面には雪が降る
- 雪山は **Three.js**(3D の絵を描くライブラリ。MIT ライセンス・登録不要・jsdelivr の CDN から読む)で、MapLibre の custom layer(= 地図に自分で描く層)に重ねる(`public/snow-map/snow-mountain-3d.js`)。形はプログラムで作る(すその広い山を、雪山ごとに違うノイズででこぼこに。白い雪・少し青い影・てっぺんのきらめき・地面の薄い影)。150 個でも軽いように、形は 6 種類を使い回す(InstancedMesh)。押した雪山は、画面の上の雪山との距離で選ぶ
- 大きさ・ノイズ・押した雪山の選び方の計算は `public/snow-map/snow-mountain.js`(テストは `tests/snow-mountain.test.ts`)、データは `GET /api/snow-map`(`src/help-requests/snow-map.ts`)
- `?demo` を付けると見本の雪山を 150 個出す(まだ雪かきが少ないときの説明用)
- **カロリーはアプリで測る**: 若者向けアプリが加速度から測った消費カロリーを、スコップの回数と一緒に送る(`POST .../scoops` の `calories`)。参加者の `helpers[].calories` に残す(表の変更はいらない)。測っていない人は時間から出した値

## 来てくれる人の現在地(お年寄りの待機画面・若者の場所・詳細の画面)

タクシーアプリの「GO」のように、向かっている若者の現在地を、お年寄りの待機画面に出します。提案は [../proposals/03-elder-side.md](../proposals/03-elder-side.md)。

**若者(`helper-place.html`・`public/liff/location-share.js`)**

- 最初に「お年寄りにあなたの位置が見えます(到着するまで)」と出し、[位置を共有する] / [共有しない] を選んでもらう。選んだ結果は端末(localStorage の `bibai-location-share`)に覚え、次から聞き直さない。切り替えのボタン(「位置の共有をやめる」/「📍 位置を共有する」)はいつも出す。共有しなくても参加はできる
- 共有するなら `navigator.geolocation.watchPosition` で位置を読み、**15 秒ごと**に `POST /api/help-requests/:id/location` へ送る。前に送った位置から 10m 未満しか動いていなければ送らない(ただし 60 秒たったら送り直す)
- [到着しました!]・[参加をやめる]・雪かきが始まって画面が移るときに止める。画面が隠れたら止め、見えたら再開する。すでに到着している人には共有の欄を出さない
- 位置が取れない・拒否されたら「位置を取得できませんでした(参加はそのまま続けられます)」
- テストモードのときだけ [🧪 位置をまねる] が出る。押すたびに、お年寄りの家(なければ美唄の中心)から南西へ約 1km の場所から、150m ずつ家へ近づく位置を送る(PC で試す用。共有の選択に関係なく送る)

**サーバー**

- 位置は参加者の記録(`help_requests.helpers` の jsonb の各人)に `location` として入るので、Supabase の表の変更はいらない
- 到着(arrive)するとその人の `location` を消す。参加の取り消し(leave)では参加者の記録ごと消える
- **見えるのは依頼したお年寄り本人だけ**(`src/help-requests/views.ts`)。ほかの参加者・送った本人・ゲスト・一覧には出さない。お年寄りにも、未到着で状態が accepted / working、かつ **30 分以内** の位置だけを出す

**お年寄り(`help-waiting.html`・`public/liff/elder-live-map.js`)**

- 参加あり(accepted)、または雪かき中でまだ着いていない人がいる間、「いま来てくれている人」の地図と一覧を出す。地図には家の印「おうち」(依頼に位置があるときだけ。なければ美唄の中心あたりを出す)と、向かっている人のアイコン(名前つき)。全員が入るように自動で寄せる。操作はいらない
- 一覧は 1 人ずつ: 「〇〇さん あと約 5 分」+「1 分前の位置」/ 着いた人は「〇〇さんが着きました」/ 位置がない人は「〇〇さん」+「位置の共有なし」。家の位置がないときは「あと約〇分」の代わりに「向かっています」
- 数秒ごと(4 秒)の読み直しのたびに更新する
- **到着の目安** = まっすぐの距離(ハバーサイン公式)÷ 歩く速さ 4.8km/h(= 80m/分)、切り上げ、最低 1 分。計算は `public/liff/eta.js`(純粋関数。テストは `tests/eta.test.ts`)
- 見た目だけ確かめるときは `help-waiting.html?preview=live`(API を呼ばずに、向かっている人・共有なしの人・着いた人の例を出す)

## スコアの計算(仮の値。`src/help-requests/score.ts`。詳しくは [04-ranking.md](04-ranking.md))

- 雪かきのポイント = 作業分数(120 分まで)× 100 + 雪の重さ kg(2,000kg まで)× 2(参加者全員に入る)
- 雪の重さ kg = 面積㎡(5,000㎡ まで)× 積雪の深さ m × 100。積雪の深さは天気予報(Open-Meteo)のいまの値。取れなければ 0.3 m
- 評価のポイント = 星 × 100(いいねが届いたときに加算)
- 勧誘ポイント = 誘った人が初めて雪かきを終えたら、誘った人に 500(1 人につき 1 回)・誘われた人に「はじめての雪かき」200
- 再会ボーナス = 前の別の依頼(done)でも一緒だった参加者 1 人につき 150(依頼ごと)
- 消費カロリー = 5.5(METs)× 60kg × 時間 h × 1.05

## ローディング(画面の切り替えのクッション)

- 「テストのデータを消す」ボタン(確認あり)→ `POST /api/test/reset`。テスト用の利用者が関わったデータだけを消す: 依頼した人か参加者がテスト用の ID の依頼・テスト用の ID の役割・本人確認の結果・テスト用の ID の招待コードと、テスト用の ID が誘った / 誘われた招待の記録。ほかの人のデータは消さない
- ランキングや仲間ゲージにテスト用の利用者が出ることがある(名前の「(テスト)」で分かる。消すボタンで消える)
- 使い方の例: 「テスト用のお年寄り」で依頼を出す → 「自分」や「テスト用の若者 A / B」に切り替えて参加 → 雪かき → 「テスト用のお年寄り」に戻っていいねを送る

## ひな形を作り込むときのメモ

- 見た目の共通部分は `public/liff/template.css`、全ページ共通の処理は `public/liff/template.js`(デザインの方針は [design.md](../design.md))
- 演出(カウントアップ・雪の紙吹雪)は `public/liff/effects.js`、仲間ゲージは `public/liff/community-gauge.js`
- 招待リンク(`?invite=`)の受け取りは `public/liff/invite-accept.js`(`template.js` と `main.js` から読み込むので全画面で動く)、「友だちを誘う」は `public/liff/invite-share.js`
- 地図の部品は `public/liff/map.js`、面積の計算は `public/liff/geo.js`、到着の目安の計算は `public/liff/eta.js`、依頼 1 件の画面の共通処理は `public/liff/request-page.js`
- 灰色の点線の箱(`class="placeholder"`)が「ここに〇〇が入る予定」の印
- 「メニューを最初に戻す」ボタンは `template.js` が自動で出す
- Miro のフォームには「名前・位置情報・雪の深さ(体の部位で表す)・道具(必須ではない)」がある。サーバーは受け取れるようになったので、`help-request.html` に入力欄を足せば送られる([Gemini 向けメモ](../guides/help-request-form-for-gemini.md))

> 参加を取り消す(`POST /api/help-requests/:id/leave`)と、その人の本人確認も取り消される。次に参加するときは、もう一度顔の照合が必要。
