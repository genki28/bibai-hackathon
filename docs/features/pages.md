# 画面(ページ)の一覧

LIFF(= LINE の中で開く Web 画面)のページと、その URL の一覧です。
画面の流れは Miro の遷移図(チームのボード「20261122ハッカソン」)をもとにしています。

## URL の書き方

| どこで開く | URL |
| --- | --- |
| LINE の中(リッチメニューやトークのリンク) | `https://liff.line.me/{LIFF ID}/{ページ}` |
| 自分の PC(`npm run dev` で起動中) | `http://localhost:3000/liff/{ページ}` |
| デザインのおためし(Python の簡易サーバー) | `http://localhost:8000/{ページ}?preview` |

`{ページ}` には下の表のファイル名が入ります(例: `help-waiting.html`)。
`?id=依頼ID` が付くページは、どの依頼の画面かを URL で受け取ります(画面どうしが自動で付けます)。

## ページ一覧

### お年寄り向け

| # | ページ | ファイル | 状態 | 中身 |
| --- | --- | --- | --- | --- |
| 1 | 助けを呼ぶフォーム | `help-request.html` | 動く | 雪の多さを選んで「よぶ」。送れたら 2 へ。すでに呼んでいる人は開くと 2 へ移る |
| 2 | 待機画面 | `help-waiting.html` | 動く | 受注状況を数秒ごとに更新(お待ちください → 受注が完了しました+向かってくる人の名前 → 雪かき中です → 終わったら「いいねを送る」)。赤い [取り消し] で本当に取り消す |
| 3 | いいね | `thanks.html?id=` | 動く | 来てくれた人ごとに星 1〜5 を付けて [送信](1 回だけ) |

### 若者向け

ランキング・助けに行く・場所・待機中の画面には、下に [ランキング] [助けに行く] のタブが出ます。

| # | ページ | ファイル | 状態 | 中身 |
| --- | --- | --- | --- | --- |
| 4 | ランキング | `ranking.html` | 動く | デイリー(日本時間の今日)/ 総合 の切り替え。順位・名前・ポイント。自分を目立たせる |
| 5 | 助けに行く | `go-help.html` | 動く | 「〇件募集があります」、エリアで絞り込み、一覧(5 件ずつ・前へ / 次へ)→ 場所(大まかな地図。円で示すだけ)→ 確認の小窓「助けに行きますか?」→ 確定で参加 → 本人確認へ |
| 6 | 場所・詳細 | `helper-place.html?id=` | 動く | 詳しい地図(ピン)・住所・募集者の名前。[取消] で参加をやめる、[到着しました!] で 7 へ |
| 7 | 待機中 | `helper-gather.html?id=` | 動く | 参加者一覧(👑 がリーダー)と「〇/〇人集合」を数秒ごとに更新。リーダーだけ [雪かき開始]。開始されたら全員が 8 へ |
| 8 | 雪かき中 | `helper-working.html?id=` | 動く | 雪だるまと雪かきのアニメーション、経過時間(開始時刻はサーバーにあるので、開き直しても続きから)。[雪かきを終える] で 9 へ。だれかが先に終えたら 10 へ |
| 9 | 範囲 | `snow-area.html?id=` | 動く | 地図をタップして範囲を描く。面積(㎡)を表示。[1 つ戻す] [やり直す] [雪かき終了!] |
| 10 | お疲れ様 | `finish.html?id=` | 動く | スコアを大きく表示。作業時間・消費カロリー・面積・雪の重さ・ポイントの内訳。[メイン画面に戻る] で 4 へ |

### 共通・そのほか

| ページ | ファイル | 中身 |
| --- | --- | --- |
| トップ | `index.html` | LIFF の動作確認と雪の予報 |
| 本人確認(デモ) | `identity.html` | マイナンバーカードの本人確認のデモ(実際の読み取りはしない)。`?next=〇〇.html&id=依頼ID` が付いていると、確認後 1.5 秒ほどで次の画面へ自動で進む |

## 画面のつながり

```text
お年寄り:  [たすけて] → 1 フォーム → 2 待機画面 ─(取り消し)→ 取り消しました。
                                         └(雪かきが終わる)→ [いいねを送る] → 3 いいね

若者:      [ランキング] → 4 ランキング
           [助けに行く] → 5 助けに行く(一覧 → 場所 → 確認の小窓 → 確定 = 参加)
             → 本人確認 →(自動)→ 6 場所・詳細 →[到着しました!]→ 7 待機中
             →(リーダーが開始)→ 8 雪かき中 →[雪かきを終える]→ 9 範囲
             →[雪かき終了!]→ 10 お疲れ様 →[メイン画面に戻る]→ 4 ランキング
```

## 依頼の状態

```text
waiting(募集中)→ accepted(だれか参加)→ working(雪かき中)→ done(終了)
どこからでも(終了前なら)→ cancelled(お年寄りが取り消し)
```

- 1 つの依頼に参加できるのは 5 人まで(仮)。最初に参加した人がリーダー
- 参加者全員がやめると waiting に戻る。リーダーがやめると、次に参加した人がリーダーになる

## API の一覧

すべて `{ success: true, data }` か `{ success: false, error: "日本語のメッセージ" }` で返します。
入力がおかしいと 400、権限がないと 403、依頼がないと 404、いまの状態ではできないと 409。

| API | 入力 | 中身 |
| --- | --- | --- |
| `POST /api/help-requests` | `{ userId, amount?, name?, address?, lat?, lng?, depth?, tools? }` | 依頼を登録(同じ人の終わっていない依頼があればそれを返す) |
| `GET /api/help-requests` | なし | 参加できる依頼の一覧(大まかな情報だけ。名前・住所・正確な位置は出さない) |
| `GET /api/help-requests/mine/:userId` | なし | お年寄りの進行中の依頼(取り消し・いいね済みは除く)。なければ null |
| `GET /api/help-requests/:id?userId=` | なし | 依頼の詳細。本人と参加者にはすべて、ほかの人には大まかな情報だけ |
| `POST /api/help-requests/:id/join` | `{ userId, displayName }` | 参加する |
| `POST /api/help-requests/:id/leave` | `{ userId }` | 参加をやめる(雪かき開始前だけ) |
| `POST /api/help-requests/:id/arrive` | `{ userId }` | 到着した |
| `POST /api/help-requests/:id/start` | `{ userId }` | 雪かき開始(リーダーだけ) |
| `POST /api/help-requests/:id/finish` | `{ userId, areaM2 }` | 雪かき終了(面積は 0〜2000㎡)。スコアを計算して保存 |
| `POST /api/help-requests/:id/cancel` | `{ userId }` | 依頼の取り消し(依頼した本人だけ) |
| `POST /api/help-requests/:id/thanks` | `{ userId, ratings: { 若者のユーザーID: 1〜5 } }` | いいね(依頼した本人だけ・1 回だけ) |
| `GET /api/ranking?period=daily\|total&userId=` | なし | ポイントの多い順。`userId` を付けると自分に `isMe: true` が付く |

## スコアの計算(仮の値。`src/help-requests/score.ts`)

- 雪かきのポイント = 作業分数 × 100 + 雪の重さ kg × 10(参加者全員に入る)
- 雪の重さ kg = 面積㎡ × 積雪の深さ m × 100。積雪の深さは天気予報(Open-Meteo)のいまの値。取れなければ 0.3 m
- 評価のポイント = 星 × 100(いいねが届いたときに加算)
- 消費カロリー = 5.5(METs)× 60kg × 時間 h × 1.05

## まだできていないこと・注意

- データは Supabase に保存する(`SUPABASE_URL` と `SUPABASE_SECRET_KEY` がないときはサーバーのメモリに置き、再起動で消える)
- 書き込み API は送られてきた userId をそのまま信じている。**LINE の ID トークンでの本人確認は未実装**
- 再会ボーナス・勧誘ポイントは未実装
- 依頼に位置がないときは、美唄市の中心あたりを地図に出す
- 参加中の若者が途中で画面を閉じると、「助けに行く」からは戻れない(同じ URL を開き直せば続きから)
- 地図は Leaflet(unpkg.com から読み込み)と OpenStreetMap のタイルを使う。出典は地図の右下に出る

## ひな形を作り込むときのメモ

- 見た目の共通部分は `public/liff/template.css`、全ページ共通の処理は `public/liff/template.js`
- 地図の部品は `public/liff/map.js`、面積の計算は `public/liff/geo.js`、依頼 1 件の画面の共通処理は `public/liff/request-page.js`
- 灰色の点線の箱(`class="placeholder"`)が「ここに〇〇が入る予定」の印
- 「メニューを最初に戻す」ボタンは `template.js` が自動で出す
- Miro のフォームには「名前・位置情報・雪の深さ(体の部位で表す)・道具(必須ではない)」がある。サーバーは受け取れるようになったので、`help-request.html` に入力欄を足せば送られる([Gemini 向けメモ](../guides/help-request-form-for-gemini.md))
