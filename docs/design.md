# デザインの方針

## ユキカキ・レイド — 雪の日が、誰かとつながる日に

雪かきを、仲間と達成感を分かち合う協力ゲームとして見せます。美唄で一緒に雪かきする人が増えることが目的です。画面遷移と機能は [画面一覧](features/pages.md) のままです。

若者には「参加する → 仲間が集まる → 雪かき → 成果を受け取る」という流れを、クエストの札、参加人数、ドット絵、大きな成果の数字で伝えます。背景全体の発光や紫のグラデーションを避け、押す場所と成果が目立つようにします。

お年寄りには「いま、どうなっているか」が伝わる案内を優先します。白い状態カード、深い緑の進み具合、大きな文字とボタンを使い、待機中に繰り返し操作する必要がないことも伝えます。到着や完了を実際の依頼の状態に合わせて表示し、対応時間や安全性を保証する表現は使いません。

## 共通の見た目

| 項目 | 若者 | お年寄り |
| --- | --- | --- |
| 背景 | 深い青 `#102B3B` | 明るい冬の緑 `#EDF3EF` |
| 本文 | 雪の白 `#F2F7F7` | 深い緑 `#243D3A` |
| 案内・進み具合 | 氷の青緑 `#8FD6D1` | 深い緑 `#286250` |
| 主な操作 | 報酬の黄色 `#F5CC67` | 温かいオレンジ `#A84320` |
| ボタンの高さ | 56px 以上 | 72px 以上 |

- 共通のロゴ、12〜16px の角丸、罫線と余白で同じサービスだと伝える。
- 字は端末標準。本文は 16px 以上、説明は 14px 以上、お年寄り側は本文 19px・説明 16px を基本にする。
- 操作できる場所には、キーボード操作時にも見える枠を付ける。色だけで状態を伝えず、到着などの文字を添える。
- スマートフォンを中心に、内容は最大 520px に収める。下部メニューと本文が重ならない余白を取る。
- 「メニューを最初に戻す」はページ末尾に置き、主な操作を妨げない。

## 各画面

| 画面 | 見せ方 |
| --- | --- |
| トップ | 雪のまちのイラストと、雪かきに参加／助けを呼ぶ入口。接続情報は折りたたむ |
| 依頼一覧 | まちのイラスト、エリア選択、協力クエストの札と参加人数。募集がない場合にも説明を出す |
| 場所・参加確認 | 地図と依頼の情報をまとめ、参加する操作を黄色にする |
| 本人確認 | 共通の配色で読みやすく整える。デモであることや写真に関する注意は残す |
| 集合 | 参加者の一覧、到着状態と集合人数。名前が長い場合は折り返す |
| 雪かき中 | 既存のドット絵と人数・経過時間・レベルを残し、ゲーム画面を枠でまとめる |
| 範囲の記録 | 地図を広く取り、面積と完了する操作を目立たせる |
| 結果 | 勲章、QUEST CLEAR、ポイントと活動の内訳。既存の数字の数え上げと紙吹雪を使う |
| ランキング | 上位3人の表彰台、自分の順位、仲間の人数、友だちを誘う導線 |
| お年寄りの待機 | 進み具合と「いまの様子」。取り消す操作は枠線のボタンにする |
| お礼 | 来てくれた人ごとの大きな星と、「ありがとうを送る」ボタン |

## 実装と変更範囲

- `public/liff/snow-ui.css` が新しい共通の見た目。対象11画面の最後で読み込む。
- `template.css` と各画面に元からある見た目を、このファイルで上書きする。並行作業との衝突を小さくするため、既存の共通ファイルは変更しない。
- **助けを呼ぶフォーム `help-request.html` / `help-request.js` は別担当。今回の変更対象外。新しいCSSも読み込ませない。** 共通の処理や `loading.css` もそのままにする。
- `images/snow-town.svg` はこの画面用の図形のイラスト。追加のライブラリや外部サービスは不要。
- ドット絵、スコア計算、仲間の人数、招待、顔の照合は既存の処理を使う。新しいゲームの点数や報酬は作らない。
- 端末で「動きを減らす」を設定している場合は、CSS のアニメーションと既存の数字の数え上げ・紙吹雪を止める。ドット絵の既存アニメーションは今回変更しない。

## 手元での確認

`TEST_MODE=true`、Supabase と LINE の接続設定は空にして起動し、架空の利用者で確認します。本物の通知は送りません。

- 依頼0件と複数件、参加確認、本人確認の案内／確認済み、場所、集合、雪かき、範囲、結果、ランキング、お年寄りの待機とお礼を確認する。
- 390px と 320px のスマートフォン幅、幅の広い画面を確認する。
- `npm test` と `npm run typecheck` を実行する。
- LINE内での認証・カメラ・実際の通知は別途実機で確認する。
