# 2. 作業の流れ

毎回やることは 3 ステップだけです。

```
/start-work  →  AI にお願いして作る  →  /save-work
 (始める)                              (保存して共有)
```

## ステップ 1: 始める — `/start-work`

Claude Code で `/start-work` と打ちます。

- みんなの最新の変更を自分の PC に取り込みます。
- あなた専用の「作業場所(ブランチ)」を作ります。ここで何をしても、他の人の作業は壊れません。

## ステップ 2: 作る

やりたいことを日本語で Claude に伝えます。コツは [AI への頼み方](03-prompting.md) に。

- **1 回に 1 つ。** 「トップページを作って」→ 動いた → 「ボタンを足して」のように小さく進める。
- **動かして確かめる。** 「動かして見せて」「確認して」と頼めます。
- **困ったら `/stuck`。** エラーの画面をそのまま貼り付けても大丈夫です。

## ステップ 3: 保存して共有 — `/save-work`

キリのいいところで `/save-work` と打ちます。

- 変更を記録して(コミット)、GitHub に送ります(プッシュ)。
- 「みんなの本体(main)に入れてください」という依頼(プルリクエスト)を作ります。
- プルリクエストが取り込まれる(マージ)と、他の人の PC にも届くようになります。

こまめに保存するほど安全です。30 分〜1 時間に 1 回が目安。

## 守ってほしいこと

- **同じファイルを同時に 2 人で触らない。** 始める前に「いまから◯◯やります」とチームに一声。
- **パスワードや API キーをチャットやファイルに貼らない。** 必要になったら経験者に相談。
- **よくわからない確認が出たら、進める前に聞く。** 特に「削除」「上書き」「force」という言葉が出たとき。

## よくあること

| 起きたこと | どうする |
| --- | --- |
| 赤い文字のエラーが出た | `/stuck` と打って、エラーをそのまま貼る |
| 「コンフリクト」と言われた | 同じ場所を他の人も変えています。Claude の説明を読んで、わからなければ経験者を呼ぶ |
| 変なことになった気がする | それ以上触らず `/stuck`。保存済みのものは消えません |
| 何をすればいいかわからない | Claude に「いま何が終わっていて、次に何をすればいい?」と聞く |
