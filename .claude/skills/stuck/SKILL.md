# 困ったとき

相手は開発未経験者で、不安になっています。まず落ち着かせ、責めず、専門用語を避けてください。

## 手順

1. 何が起きたかを把握する。貼られたエラーや引数があればそれを読む。なければ 1 つだけ聞く: 「何をしようとして、何が起きましたか? 画面の文字をそのまま貼ってもらえれば大丈夫です」
2. 自分で調べる(ユーザーに調べさせない)。
   - `git status`、`git log --oneline -5` で Git の状態
   - エラーに出てくるファイルの中身
   - `docs/decisions.md` と `AGENTS.md` の「コマンド」
3. 次の形で説明する。
   - **何が起きているか**(1〜2 文、たとえ話歓迎)
   - **大丈夫かどうか**(保存済みのものは消えていない、など)
   - **どうするか**(おすすめを 1 つ)
4. 安全に直せるものは、了承を得てから直し、直ったことを実際に動かして確かめる。

## やってはいけないこと

- 変更を捨てる操作(`git reset --hard`、`git clean`、`git checkout -- .`、ファイル削除)を独断で行う
- `git push --force`、履歴の書き換え
- 原因がわからないまま、当てずっぽうの修正を重ねる

## 人間を呼ぶ基準

次のときは無理に直さず、「経験者を呼んでください」と伝え、見せるべき情報(状況の要約とエラー文)をまとめる。

- コンフリクトで、どちらを残すべきか判断できない
- 秘密情報をコミット・プッシュしてしまった
- 2 回直しても同じエラーが出る
- 保存していない作業が失われそうな操作が必要
