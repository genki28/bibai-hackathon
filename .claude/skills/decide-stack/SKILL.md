# 技術スタックを決める

チームのほとんどは開発未経験で、AI に頼んで作ります。ハッカソンなので「短時間で動くデモ」が目的です。

## 手順

1. `docs/product.md` と `docs/decisions.md` を読む。すでに決まっていれば、その内容を伝えて変更したいかを聞く。
2. 足りない情報だけを、やさしい言葉で質問する(一度に 3 つまで)。
   - 何を作りたいか(product.md が空なら、ここで一緒に埋める)
   - どこで使うか: スマホ / PC のブラウザ / そのほか
   - データを保存する必要があるか、ログインが必要か
   - AI(Claude など)の機能をアプリに組み込むか
   - 発表のとき、URL を配って触ってもらいたいか
   - チームの PC は Mac / Windows どちらか
3. 構成を **1 つおすすめ** し、必要なら代案を 1 つだけ添える。選ぶ基準:
   - AI が得意で情報が多い、定番の組み合わせ
   - Mac でも Windows でも同じ手順で動く
   - 入れるものが少なく、準備が 10 分で終わる
   - 無料で公開(デプロイ)できる
   - 迷ったら、より単純なほう。サーバーや DB は本当に必要なときだけ
4. 各項目を「何のためのものか」一言で説明し、チームの了承を得る。**了承されるまでファイルは作らない。**
5. 決まったら記録する。
   - `docs/decisions.md`: スタックの表と、決定ログに日付・理由
   - `AGENTS.md`: 「技術スタック」を決定内容に書き換え、「コマンド」にインストール / 起動 / テスト / ビルドを記入
   - `docs/01-setup.md`: 「追加で必要になるもの」に、入れるものと手順
   - `.gitignore`: そのスタックで自動生成されるフォルダ
   - `.env.example`: 必要な環境変数の名前(値は書かない)
6. ひな形(最小の動くもの)を作るかを聞く。作る場合は公式の作成コマンドを使い、起動して動くことを確認する。

## 注意

- 絶対パスや PC 固有の設定をファイルに書かない。
- バージョンや作成コマンドは記憶に頼らず、公式ドキュメントで確認する。
- 有料サービスや、クレジットカード登録が必要なものを選ぶときは、必ず事前にそう伝える。
