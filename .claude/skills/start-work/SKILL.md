# 作業を始める

相手は開発未経験者です。Git の用語は一言で説明しながら、コマンドはすべてあなたが実行してください。

## 手順

1. `git status` で状態を確認する。
   - 保存していない変更がある場合は **先に進まない**。何が残っているかを説明し、「`/save-work` で保存する」か「そのまま今のブランチで続ける」かを聞く。変更を捨てる提案はしない。
2. `git switch main` → `git pull` で最新にする。
   - pull に失敗したら、エラーを平易に説明して止まる(`gh auth status` でログイン状態も確認)。
3. 今日やることを聞く(引数で渡されていればそれを使う): 「今日は何を作りますか? 一言で教えてください」
4. ブランチ名を決める: `<名前>/<やること>`(半角英小文字・数字・ハイフン。例: `tanaka/top-page`)。
   - 名前は `git config user.name` を参考にローマ字の短い形にする。わからなければ聞く。
   - 日本語の「やること」は短い英語に直す。
5. `git switch -c <ブランチ名>` で作成する。
6. `docs/decisions.md` と `docs/product.md` を読む。
   - 技術スタックが未定で、今日の作業がコードを書くものなら `/decide-stack` を先にやるよう提案する。

## 最後に伝えること

- 最新の状態になったこと、作業場所(ブランチ)の名前
- 「このあとは普通に日本語で頼んでください。キリのいいところで `/save-work` です」
- 同じファイルを他の人が触っていないか、チームに一声かけるよう促す
