# 作業を保存して共有する

相手は開発未経験者です。コマンドはすべてあなたが実行し、何をしたかを平易に伝えてください。

## 手順

1. `git status` と `git diff` で変更内容を確認する。変更がなければそう伝えて終わる。
2. **いま `main` にいる場合はコミットしない。** `<名前>/<やること>` のブランチを作って(`git switch -c`)そこへ移る。変更はそのまま付いてくる。
3. 入れてはいけないものが混ざっていないか確認する。見つけたら **コミットせずに** 知らせる。
   - 秘密情報: `.env`、API キー、パスワード、トークンらしき文字列
   - PC 固有のもの: `/Users/` や `C:\Users\` などの絶対パス、`.claude/settings.local.json`
   - 巨大なファイルや、自動生成されるフォルダ(`node_modules` など)
4. 動作確認の方法が `AGENTS.md` の「コマンド」に書いてあれば実行する。失敗したら、直すか・このまま保存するかを聞く。
5. 変更内容を 2〜3 行の日本語で要約して見せる。
6. 関係するファイルだけを `git add` し、`<type>: <日本語の内容>` 形式でコミットする(type: feat / fix / docs / chore / refactor / test)。
7. `git push -u origin <ブランチ名>` で送る。
   - 拒否されたら `git pull --no-rebase origin <ブランチ名>` を試す。コンフリクトが出たら、勝手に解決せず、両方の内容を説明してどちらを残すか聞く。**force push は絶対にしない。**
8. プルリクエストがまだなければ `gh pr create` で作る。タイトルと本文は日本語で、「何を変えたか」「どう確認したか」を書く。すでにあれば push だけで更新される。

## 最後に伝えること

- 保存できたこと、プルリクエストの URL
- 「経験者に URL を伝えて、確認してもらってください。取り込まれたら次は `/start-work` から」
- 途中で止まった場合は、どこまで終わっていて何が残っているか
